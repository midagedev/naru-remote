## 하드웨어 입력 실측 결과 (코드 레벨)

### HW-1 (P0급 갭) 마우스 휠·트랙패드 스크롤 미수신
`MetalFramebufferView.swift:823-830`의 2핑거 팬(원격 휠)에
`allowedScrollTypesMask`가 없다 → 간접 포인터의 스크롤 이벤트(BT 마우스 휠,
iPad 트랙패드 2핑거 스크롤)가 인식기에 도달하지 않는다. 전용 팬 인식기
(`allowedScrollTypesMask = .all`, 터치 0개 허용)가 필요.

### HW-2 (P0급 갭) 마우스/트랙패드 보조 클릭 미매핑
어느 인식기에도 `buttonMaskRequired = .secondary`가 없다. 물리 우클릭이
동작하지 않거나(무시) 좌클릭으로 오인될 수 있다. 보조 버튼 전용
탭 인식기 1개 추가가 정답.

### HW-3 (P1) 시스템 포인터 미처리 — 이중 커서
저장소 전체에 `UIPointerInteraction`/`pointerStyle` 부재. iPad에서 포인터
연결 시 시스템 화살표가 원격 화면 위에 그대로 뜬다. 직접터치 모드에서는
호버 이동도 무시(`handleHoverGesture`가 `isTrackpad` 가드,
`MetalFramebufferView.swift:1162-1165`) — 마우스를 움직여도 원격 커서가
안 따라온다. 방향: 세션 뷰 위에서 시스템 포인터를 숨기고(hover 시
UIPointerStyle.hidden), 간접 장치의 호버는 모드 무관 원격 커서 이동으로.

### HW-4 (P2) 하드웨어 키 이벤트 순서 강화
`pressesBegan → onHardwareKey → Task { await model.handleHardwareKey }`
(NaruRemoteAppShell.swift:140-148) — 비구조 Task는 FIFO가 계약이 아니다.
실제로는 main-actor 동일 우선순위라 순서가 지켜지고, 모델 내부도 await 전
동기 구간에서 enqueue하므로 재정렬 관측 확률은 낮음. 스트림/AsyncStream
직결로 강화 가능(급하지 않음).

### 확인된 정상 동작
- BT 키보드: Type 모드에서 DirectKeystrokeResponderView가 raw HID→keysym
  스트림(수식키 단독 프레스 포함, KeysymMapping+UIKit:104-106). Type 에디터
  포커스 시에는 iOS IME를 거쳐 로컬 조합(한글 OK). 이중 경로 설계 정합.
- 제스처(터치): 즉시 싱글탭/더블탭/2핑거 우클릭/핀치 로컬 줌 — spec 011 US3
  구현 확인, 라이브 E2E까지 검증됨.

## 스크린샷 감사 발견 (iPhone 실측)

1. **수식키 버튼 높이 폭주** — ModifierKeyButton이 폭만 고정(`.frame(width:)`),
   높이 무제약 → 스트립 행·독 전체가 부풀어 화면 대부분을 차지.
   → strip-ui 라운드 S1.
2. **Fn 토글이 스크롤 안** → iPhone 폭에서 화면 밖. UITest 3건 실패의 원인 축.
   → strip-ui 라운드 S2/S3 (orca #5106 패턴: 고정 배치).
3. **비세션 상태 시각 비일관**(수식키만 회색) → S4.
4. "Ready to compose locally" + Retry 동시 노출은 **테스트 픽스처 전용 상태**
   (프로덕션은 failed 시 독 숨김, NaruRemoteAppShell.swift:359-368) — 결함 아님.
5. UITest의 `ipad-*` 태그 스크린샷은 실제로는 iPhone 회전 캡처다 — 증거
   라벨이 기기를 오표기. 별도 iPad 실행으로 보완(이번 감사에서 수행).
