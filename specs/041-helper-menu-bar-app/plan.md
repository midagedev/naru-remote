# Implementation Plan: Naru Helper Menu Bar App

**Feature**: `specs/041-helper-menu-bar-app/spec.md`
**Created**: 2026-09-05
**Status**: Active

## Summary

Turn the helper's shipping form from three CLI processes into one signed,
notarized macOS menu bar app, without changing the wire. Everything the
app needs that is not UI moves into `NaruHelperKit` first (so it is
tested under `swift test` and shared with the CLI), then a thin SwiftUI
`MenuBarExtra` app is generated by a second XcodeGen spec that consumes
the root package as a local dependency.

## Architecture

### Layering

```
NaruRemoteCore  (offer codec, HelperPairingSecret, catalogs — unchanged)
      ▲
NaruHelperKit   (+ this feature: runtime that owns both listeners,
      ▲           pairing-state store with revoke, host info, app status
      │           catalog, pairing session model, QR image, diagnostics)
      ├── NaruHelper        (CLI — refactored to call Kit; behavior unchanged)
      └── NaruHelperApp     (NEW — macOS app, SwiftUI MenuBarExtra, XcodeGen)
```

Rule: `NaruHelper/App/` holds views and AppKit glue only. Anything with
a decision in it (status aggregation, revoke semantics, login-item state
machine, diagnostics text) lives in the Kit with a test.

### Build

- **Root `Package.swift`** gains a `.library(name: "NaruHelperKit")`
  product so an Xcode project can depend on it.
- **`NaruHelper/project.yml`** (new XcodeGen spec) generates
  `NaruHelper/NaruHelper.xcodeproj` with:
  - `NaruHelperApp` — `type: application`, `platform: macOS`,
    deployment target 14.0, product name `Naru Helper`, bundle id
    `com.naruremote.helper`, `LSUIElement: true`, dependency on local
    package `..` product `NaruHelperKit` (and `NaruRemoteCore`). Hardened
    runtime on; no App Sandbox (Accessibility + Screen Recording).
  - `NaruHelperAppUITests` — `bundle.ui-testing`, macOS.
- The root `project.yml` (iOS) is untouched. Two projects avoid module
  name collisions between the iOS framework targets and the package.
- The CLI target keeps building via SwiftPM; `scripts/install-naru-helper-dev-app.sh`
  keeps producing `com.naruremote.helper.dev` for benchmarks.

### Runtime pieces (Kit)

| Piece | Responsibility | Test |
| --- | --- | --- |
| `NaruHelperListenerRuntime` | Owns text + video servers in one process; exposes per-listener `NaruHelperListenerState` (`.starting/.listening(port)/.portInUse(port)/.failed/.stopped`) via a callback; `start()`/`stop()` | Bind a taken port → `.portInUse`; both up → both `.listening` |
| `NaruHelperPairingStateStore` (extend) | `currentSecret()`/`currentFingerprint()` return `nil` when the file is **absent** (ENOENT) and keep the cache only on transient failure; new `revoke()` removes the file and clears the cache | FAIL-first: today absent ⇒ cached token returned |
| Handlers (`NaruHelperNetworkRequestHandler`, `NaruHelperVideoTransportRequestHandler`) | Provider type becomes `@Sendable () -> String?`; attached provider returning `nil` ⇒ refuse with `.revoked` (never fall back to the launch-time secret). New optional `onAuthorizedRequest: @Sendable () -> Void` fires after a proof is accepted | Revoke test through both handlers |
| `NaruHelperPairingHostInfo` | Lifted from `main.swift`: label, CGNAT addresses, MagicDNS reverse lookup | Pure address-filter test on synthetic `sockaddr` list |
| `NaruHelperTextBridgeLive` | Lifted `capabilityResponse()` / `insert(request:)` factories | Compile + existing CLI tests |
| `NaruHelperPairingSession` | `begin(store:, vncPassword:)` → rotates, encodes offer via `NaruPairingOfferWire`, produces `CGImage` QR (CoreImage, nearest-neighbor scale); `end()` drops the image | Offer string equals CLI encoder output for fixed inputs; image non-nil, square |
| `NaruHelperAppStatus` | Fixed-catalog aggregate: permissions (Accessibility/ScreenRecording granted|missing), listeners, pairing (`notPaired/paired/connected`), login item (`on/off/requiresApproval/unavailable`), version | Diagnostics text contains no token/fingerprint/code/address (property test with a seeded state) |
| `NaruHelperLoginItem` | Protocol over `SMAppService.mainApp` (register/unregister/status) + a fake for tests | State machine test with the fake |

### App pieces (`NaruHelper/App/`)

- `NaruHelperApp.swift` — `@main`, `MenuBarExtra("Naru Helper", systemImage:)` with menu style; single-instance check in `applicationWillFinishLaunching` (activate existing `com.naruremote.helper`, then `exit(0)`).
- `HelperAppModel` (`@MainActor ObservableObject`) — wires runtime, store, probes, login item; refreshes permissions on a 2 s timer while any window is open and on `didBecomeActive`; owns `PairingSession`.
- `PairingWindow` — QR (min 320 pt), permission rows with **Open System Settings** (`x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` / `?Privacy_ScreenCapture`), optional VNC password `SecureField`, **Copy code**, "Paired" transition on `onAuthorizedRequest`.
- Menu: status line, permission lines, **Pair with iPhone…**, **Start at login** toggle, **Revoke pairing…** (confirmation alert), **Copy Diagnostics**, version, **Quit**.

### Release

`scripts/release-naru-helper.sh`: `xcodegen generate --spec NaruHelper/project.yml`
→ `xcodebuild archive` (Developer ID Application, team XEF9KH7N43, hardened
runtime) → `-exportArchive` with `scripts/ExportOptions-helper.plist`
(`method: developer-id`) → `ditto -c -k` zip → `xcrun notarytool submit
--key ~/.appstoreconnect/private_keys/AuthKey_$ASC_KEY_ID.p8 --key-id
--issuer --wait` (same credential file as `testflight-upload.sh`) →
`xcrun stapler staple` → `spctl --assess -vv --type execute` → write
`artifacts/app-store/<date>-helper-<version>/release.md` → optional
`gh release upload`. Credentials never in argv beyond what `notarytool`
requires; never in the repo.

## Residual Risks

- `SMAppService` on macOS 14 may report `.requiresApproval`; the UI must
  show that state and deep-link to Login Items settings. Not testable in CI.
- Screen Recording TCC for a hardened-runtime Developer ID app requires
  the correct signature at first grant; a debug build signed with the
  Apple Development identity gets its own grant. Documented in quickstart.
- Notarization needs network + ASC key; the script runs only on the
  founder's Mac. Not a CI gate.
